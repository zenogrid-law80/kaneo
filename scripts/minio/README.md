# Local Docker MinIO

Add local file storage to the bundled Kaneo Compose deployment. MinIO stores
objects in the `minio_data` Docker volume; the bucket stays private and Kaneo
uses a dedicated account with access to that bucket only.

## Configure

Keep the existing Kaneo `.env`. Create a separate storage credential file:

```sh
cp .env.minio.sample .env.minio.local
chmod 600 .env.minio.local
```

Replace both password placeholders with different values generated by
`openssl rand -hex 32`. Do not commit `.env.minio.local`.

## Start

From the repository root:

```sh
docker compose --env-file .env --env-file .env.minio.local \
  -f compose.yml -f compose.minio.yml up -d --build
```

If you already use a local `compose.override.yml`, include it explicitly before
the MinIO override:

```sh
docker compose --env-file .env --env-file .env.minio.local \
  -f compose.yml -f compose.override.yml -f compose.minio.yml up -d --build
```

Loading both env files preserves existing database settings while the storage
override takes its credentials from `.env.minio.local`. Existing AWS settings in
Kaneo's `.env` remain unchanged. Clear any exported `S3_*` or `MINIO_*` variables
from other deployments first, since shell variables take precedence over files.
The images build pinned official
MinIO and mc source releases. Initialization creates the bucket and account and
can run again with the same credentials. Kaneo starts after initialization.

- Kaneo: <http://localhost:5173>
- MinIO console: <http://localhost:9001>, using `MINIO_ROOT_USER` and
  `MINIO_ROOT_PASSWORD` from `.env.minio.local`.
- S3 endpoint: <http://minio.localhost:9000>.

The `minio.localhost` network alias resolves to MinIO inside Docker and to
loopback in browsers that support `.localhost` names. Both the API and browser
must reach the same endpoint because uploads use signed URLs. Ports 9000 and
9001 are bound to host loopback. This configuration is for local use; remote
deployments need a shared reachable hostname and HTTPS.

Use the same Compose arguments for subsequent commands. Keep the volume when
stopping containers; `down -v` deletes stored files. Changing the storage endpoint
does not migrate attachments from a previous S3 bucket.
